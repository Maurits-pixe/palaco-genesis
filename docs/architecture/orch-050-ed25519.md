# ORCH-050 — Real Ed25519 signature-byte verification

Status **DRAFT / HOLD**. Stacked on ORCH-049 (#216).

This candidate introduces a real Ed25519-dalek strict signature verifier for the exact 32-byte SHA-256 ORCH-047 receipt statement reconstructed by ORCH-049. Key references are SHA-256 hashes of public-key bytes. The verifier refuses a nonmatching key ID, altered statement, altered signature and signatures from other keys.

## Explicit limits

- The public key is provided to the verifier by its caller. This module does **not** decide whether the key is registered, authorized, revoked, expired or bound to a human.
- A valid signature proves possession of a corresponding signing secret, not operator authority.
- Neither ORCH-050 nor its predecessors reserve replay nonces durably or provide trusted monotone time.
- No filesystem changes, marker quarantine, generation activation or private memory are implemented.
- Test signing keys are fixed public fixtures; they are never production credentials.
- Cargo.lock must be regenerated and committed after dependency resolution before a reproducible release candidate can be considered.

Independent human cryptographic and provenance review is required. TRIAS: execution HOLD. ORACLE: cryptographic bytes are verified within the tested fixture only. MENTOR: next implement governed key registry/revocation and durable nonce ledger; preserve offline-only operation.
